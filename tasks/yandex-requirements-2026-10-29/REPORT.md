## Найденные проблемы и риски

**Покупки: 1.13.1–1.13.2.** В архиве 18 платёжный адаптер не вызывает `consumePurchase`, превращает чеки в список ID и не сохраняет `purchaseToken`. Магазин основной версии восстанавливал только `removeAd`; расходники не перебирались. Из каталога извлекаются цена и код валюты, но отсутствует `getPriceCurrencyImage`, а UI выводит только строку цены. Это обнаружено по коду адаптера и магазина, без проведения реальной оплаты. [Требования к покупкам](https://yandex.ru/dev/games/doc/ru/requirements/1/13), [обработка чеков](https://yandex.ru/dev/games/doc/ru/sdk/sdk-purchases).

В новой ветке добавлены восстановление всех товаров магазина, иконка валюты и обработка чеков с сохранением перед consume. Локальные тесты ошибок и повторной выдачи прошли. Старый архив 18 от этого не изменился; для отправки нужен новый проверенный экспорт. Платформенная проверка остаётся открытой.

**Готовность: риск по 1.19.2–1.19.3.** В основной версии `GameIsReady.Start` ждёт только `GameSdkReadiness.IsReady`, затем сразу отправляет ready/start. `GameManager.LoadLevel` запускает `LevelIntroSandAnimator`, который временно останавливает песок, и тут же вызывает `SandEconomyHud.OnLevelLoaded` с ещё одним GameplayStart. Нужно измерить первый интерактивный кадр и последовательность SDK-событий; по одному чтению кода нельзя объявить запуск корректным. Исправление платежей этот путь не меняет. [Семантика ready/start/stop](https://yandex.ru/dev/games/doc/ru/sdk/sdk-game-events).

**Промо: риск по 5.1.1.2.** В широких TR/DE скриншотах игровое поле небольшое, большая часть кадра занята фоном. Это реальные игровые кадры, однако их композицию стоит укрупнить или отдельно подтвердить по исключению для качественной демонстрации механики. Автоматически считать весь фон игровым полем нельзя; окончательный отказ модерации здесь не утверждается. [Пояснение к композиции скриншотов](https://yandex.ru/dev/games/doc/ru/requirements/5/1/1/2).
