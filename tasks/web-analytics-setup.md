# Аналитика WebGL

Установлены GameAnalytics 8.1.0 (встроенный UPM-пакет `Packages/com.gameanalytics.sdk`) и официальный модуль Your Games Metrica 1.02. Используется Яндекс.Метрика для браузера. Мобильная AppMetrica не подключается.

В Unity: **Window → Sand → Analytics → Create or Select Web Settings**. Команда создаёт/выбирает настройки и сохраняет введённые ключи.

1. В `Assets/PluginYourGames/Resources/SettingsYG2.asset`, секция **Metrica**, указать **Metrica Counter ID** своего счётчика. Enable и Use Yandex Metrica включены.
2. В `Assets/Resources/GameAnalytics/Settings.asset`, платформа **WebGL**, указать **Game Key** и **Secret Key** из настроек игры GameAnalytics.
3. В счётчике Метрики создать цели типа «JavaScript-событие» с идентификаторами `level_started`, `level_completed`, `level_restarted`, `level_abandoned`, `level_failed`, `tutorial_completed`, `bonus_used`, `video_ads_available`, `interstitial_shown`, `rewarded_shown`, `video_ads_success`, `resource_changed`, `buy_inapp`, `purchase_beginner_kit`, `purchase_premium_kit`, `purchase_gold_300`, `purchase_gold_700`, `purchase_gold_1200`, `purchase_remove_ads`. Номер конкретного уровня передаётся параметром `level` (1–300). Для первых 30 уровней дополнительно созданы отдельные цели старта и победы для последовательных воронок; для остальных уровней используются общие события с параметрами.
4. После WebGL-сборки проверить на целевой площадке старт, победу и перезапуск. В GameAnalytics это progression `campaign → level_001…level_300` со статусами Start/Complete/Fail; остальные действия — design-события `gameplay:*`. В Метрике — соответствующая цель и её параметры.

Каждая попытка получает отдельный `attempt_id`, номер попытки, уровень, тему, механики, длительность, количество ходов и бустеров. Повторный callback победы не дублирует прохождение. Перезапуск завершает предыдущую попытку; переключение незаконченного уровня записывает уход. Закрытие вкладки не гарантирует callback Unity, поэтому отток следует также считать по начатым без завершения попыткам. В игре нет автоматического поражения от заполненной ленты; `level_failed` предусмотрен для явного поражения, а отладочный пропуск не считается победой.

MirraSDK продолжает обслуживать платформу, рекламу и сохранения. В Your Games поле Basic/Platform намеренно пустое и отключено автоматическое применение настроек, чтобы второй SDK не запускал платформу повторно и не менял шаблон Mirra.

`interstitial_shown` и `rewarded_shown` отправляются через существующий WebGameAnalytics → YG2.MetricaSend только из callback открытия рекламы. Параметры: `adType` (`interstitial` или `rewarded`), `placement` (для rewarded — место получения бонуса), `result=shown`, `level`, `level_id`, `progressMarker` (номер уровня с 1). Повторный callback открытия одного запроса не дублирует показ. Недоступность, ошибка до открытия и бонус без просмотра при `no_ads` не записывают показ. Закрытие rewarded без награды сохраняет факт показа; `video_ads_success` отправляется только после успешного просмотра реально открытой рекламы. Закрытие интерстициала обрабатывается через второй аргумент MirraSDK, после закрытия, а не открытия.

Проверки callback рекламы и завершения уровней: `powershell -File Tools/check_ad_analytics.ps1` (путь к Unity Data можно передать через `-UnityData`). Проверка передачи целей в JavaScript-мост Метрики: `node Tools/check_web_analytics.cjs`. Используются имитации SDK, production-события не отправляются.

`buy_inapp` фиксирует только подтверждённую MirraSDK новую покупку: все шесть товаров магазина, включая монеты, наборы и отключение рекламы. Параметры `product_id` и `name` содержат ID товара, `result=success`, `level` — номер уровня с 1. Повторный callback успеха одного запроса игнорируется. Ошибки оплаты и RestorePurchases не создают новую покупку. Денежная сумма и выручка этим событием не передаются. Проверки callback покупки входят в `Tools/check_ad_analytics.ps1`.

В счётчике 112386670 через интерфейс Метрики созданы цели с точным совпадением идентификатора: `level_completed` (669604937), `video_ads_started` (669604948), `video_ads_success` (669605164), `buy_inapp` (669605805). Создание целей проверено; поступление реальных событий из опубликованной сборки не проверено.

Показы разделены на `interstitial_shown` (цель 669606027) и `rewarded_shown` (669606127). Прежняя общая цель `video_ads_started` сохранена в кабинете; обновлённый код использует две отдельные цели.

Успешная новая покупка отправляет два события: одно общее `buy_inapp` и одно для товара:

| ID товара Mirra | Событие Метрики | ID цели |
| --- | --- | --- |
| beginerKit_150 | purchase_beginner_kit | 669606163 |
| premium_kit_75 | purchase_premium_kit | 669606182 |
| gold_300 | purchase_gold_300 | 669606252 |
| gold_700 | purchase_gold_700 | 669606350 |
| gold_1200 | purchase_gold_1200 | 669606355 |
| removeAd | purchase_remove_ads | 669606360 |

Все цели созданы с точным совпадением через интерфейс счётчика и проверены в списке. Общий счётчик покупок смотрите по `buy_inapp`: складывать его с отдельными товарами не нужно, это два представления одних покупок.

События буферизуются до готовности каждого сервиса отдельно. Editor, предпросмотр и проверки не отправляют production-события. Без ID/ключей отправка соответствующему сервису не запускается.

Проверены логика попыток, JavaScript-мосты с имитацией SDK и компиляция WebGL-веток C#. В установленном Unity отсутствует WebGL Build Support, поэтому IL2CPP-сборка и поступление событий в реальные кабинеты пока не проверены.

Официальная документация: [Your Games Metrica](https://max-games.ru/plugin-yg/doc/metrica/), [GameAnalytics Unity](https://docs.gameanalytics.com/event-tracking-and-integrations/sdks-and-collection-api/game-engine-sdks/unity/).

## Бустеры, перезапуски, расширения и первые 30 уровней

- `bonus_used` (669614094) — успешное расходование бустера через BoosterService.TryConsume. Параметры `level`, `level_id`, `booster_type`, `level_booster` (например `level_006:magnet`); сохранены `bonusType` и `progressMarker`. Отдельные цели: `booster_magnet_used` (669614128), `booster_transparent_used` (669614137, заполнение), `booster_shuffle_used` (669614175). Общую цель и цели типов не складывать: это те же использования.
- `level_restarted` (669617420) — каждый перезапуск с контекстом прежнего уровня перед загрузкой новой попытки.
- `conveyor_expanded` (669617539) — одно достижение на одно успешное расширение ленты. Параметры `level`, `level_id`, `placement=conveyor_slot`. Ёмкость не передаётся. Отмена, ошибка, повторный или устаревший callback не увеличивают число расширений. Два успешных расширения на уровне дают два события этого уровня.
- Для количества по уровням использовать отчёт «Параметры цели», выбрать нужную цель и параметр `level`/`level_id`, метрику «Количество событий» (достижения), а не количество посетителей или визитов. Ключи новых параметров появятся после получения первых событий из новой сборки.
- `level_started` (669614090) и `level_completed` продолжают работать для всех уровней. Для уровней 1–30 каждое начало/завершение дополнительно отправляет `level_001_started` / `level_001_completed` … `level_030_started` / `level_030_completed`. Победа отправляется один раз на попытку. Повторное прохождение — новая попытка, уровень 31+ не создаёт отдельные события. Полный проверенный список 67 новых целей: `tasks/level-funnel-goals.json`.

В кабинете 112386670 сохранены четыре последовательные воронки без ограничения окна (до 10 шагов в одной воронке):

1. Старт уровня 1 → победы уровней 1–9.
2. Победы уровней 9–18.
3. Победы уровней 18–27.
4. Победы уровней 27–30.

Ссылки: `tasks/level-funnels.json`. Открыть через «Отчеты → Воронки». Воронки считают пользователей в последовательности событий; повторные использования бустеров/расширений считать через достижения соответствующих целей. Разбиение покрывает переходы до уровня 30, но процент каждой части относится к её первому шагу; это не единый процент от старта уровня 1. В сохранённых ссылках оставлен исходный период 8–17 декабря 2025; для новых данных выбрать период после публикации новой сборки.

Проверено локально: реальный BoosterService с имитациями хранилища/SDK, все три типа, отсутствие зарядов, первые/граничные уровни, первые 30 пар целей, дедупликация завершения, контекст перезапуска и два события расширения на одном уровне; JS-мост; managed-компиляция WebGL. Production-события тестами не отправлялись. Полная IL2CPP-сборка и поступление событий после публикации не проверены. Подтверждение кабинета: `tasks/previews/metrika-level-funnels.jpg`.
